## Состав и возможности

- `src/template.html`, `src/app.js`, `src/style.css` — актуальный интерфейс. `src/legacy.html` — архив прежних отчетов; `src/dashboard.html` сохранен как предыдущий исходник.
- `src/wrapper.html` — оболочка с CSP и sandbox iframe.
- `data/observations.json` — исходные наблюдения, соответствия SKU и признаки проверки. Опубликованы с явного разрешения владельца 30.10.2026.
- `public/index.html` — готовая собранная страница со встроенными данными; её можно раздавать существующим Nginx.
- `scripts/build.py` — сборка на Python 3.10+ без сторонних зависимостей.
- `tools/parse_captures.py` — вспомогательный разбор уже сохранённого текста карточек.

Есть фильтры моделей, дилеров и производителей, сравнение предложений, графики, сводка Word и экспорт Excel. Фильтры сохраняются локально в браузере. Codex, Sites и серверная база данных для работы не нужны. Для подключаемых ресурсов нужен доступ к CDN, перечисленным в CSP.

## Ubuntu 24.04: существующий Nginx, pars.promet.pw

**Рекомендуемый вариант — статическая раздача каталога `public` без контейнера и без порта 8080.**

В каталоге клонированного репозитория или распакованного архива выполните:

```sh
python3 scripts/build.py
sudo install -d -m 755 /var/www/pars.promet.pw/public
sudo install -m 644 public/index.html /var/www/pars.promet.pw/public/index.html
```

Готовый файл уже включён в репозиторий; повторная сборка нужна после изменения данных или интерфейса.

Образец отдельного виртуального хоста находится в `deploy/nginx-pars.promet.pw.conf`. Если домен уже настроен в Nginx, **не создавайте второй server-блок с тем же именем**: установите в существующем блоке `root /var/www/pars.promet.pw/public;`, `index index.html;` и статический `location /` из образца. Сохраните существующие настройки HTTPS и сертификата. Если раньше там был `proxy_pass`, замените только соответствующий location статической раздачей.

Если конфигурации домена ещё нет, установите образец:

```sh
sudo install -m 644 deploy/nginx-pars.promet.pw.conf /etc/nginx/sites-available/pars.promet.pw
sudo ln -s /etc/nginx/sites-available/pars.promet.pw /etc/nginx/sites-enabled/pars.promet.pw
sudo nginx -t && sudo systemctl reload nginx
```

Команду создания ссылки выполняйте только если такой ссылки ещё нет. Образец слушает HTTP на порту 80; для HTTPS используйте существующую конфигурацию сертификата домена. Убедитесь, что DNS домена указывает на нужный сервер. В корень сайта копируется только `public/`, а не весь проект. После установки откройте домен по настроенному HTTP/HTTPS и проверьте интерфейс и выгрузки.

Проверка без изменения Nginx (только локально):

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory public
```

## Docker — необязательный вариант

```sh
docker compose build
docker compose up -d
```

Compose использует `127.0.0.1:8081:80`; порт 8080 не занимает. Перед запуском убедитесь, что 8081 свободен, либо измените его. `nginx.conf` относится только к Nginx внутри контейнера; конфигурация для существующего Nginx сервера находится в `deploy/`.

**Docker-сборка в среде подготовки не запускалась: Docker здесь не установлен.** Проверена сборка Python и сформированная страница. Проверку Docker при необходимости выполните на целевом сервере.

2. Обновите `own` и `analogs`, указав фактическую дату `checkedAt`.
3. Выполните `python3 scripts/build.py`.
4. Замените `/var/www/pars.promet.pw/public/index.html` новым файлом. Перезагрузка Nginx для замены HTML обычно не нужна.

Неизвестная цена обозначается `null`. `soldUnits` — накопленный счётчик сайта Железная мебель, не недельные продажи. `selected` задаёт модели, `pairs` — соответствия аналогов, `coverage` — покрытие проверки. `sku` — артикул ПРОМЕТ; `skus` — подходящие артикулы для аналога. Одно предложение с несколькими `skus` не нужно дублировать.

В `history` сохранены реальные предыдущие снимки. Ручной прогон 30.10 подтвердил цену и наличие 152 из 170 предложений; 18 требуют сверки. Графики поддерживают исторические записи, когда они добавлены. Экспорт Excel отражает текущий снимок, а подпись «Неделя 44» в интерфейсе и экспорте пока фиксированная: при изменении периода обновите её в соответствующем исходнике. Word использует выбранные наблюдения и заданный порог критичных изменений.

## Вход и автоматическое обновление (Ubuntu / Nginx)

После первоначальной настройки HTTPS выполните:

```sh
git -C /opt/promet-parser pull --ff-only
sudo bash /opt/promet-parser/deploy/install.sh
```

Установщик дважды запросит пароль для **MEBELPROMET**, ввод скрыт. Пароль и хеш не хранятся в GitHub; файл проверки — `/etc/nginx/pars.promet.pw.htpasswd`, вне корня сайта. Используется окно входа браузера Basic Auth по HTTPS. Сохраняется резервная копия конфигурации Nginx, добавляется include в существующие server-блоки этого домена; сертификат сохраняется, проверка nginx -t предшествует reload. Остальные сайты не редактируются.

Обновление программы и запуск сбора цен одной командой:

```sh
promet-parser-update
```

Git обновляется с --ff-only, локальные изменения не затираются. Сбор запускается в фоне. Если уже выполняется, второй экземпляр не стартует.
Только обновить программу/страницу без сетевого сбора: `promet-parser-update --code-only`.
Сменить пароль: `sudo promet-parser-password`.

Сбор запускается также ежедневно в **00:00 Europe/Moscow**, с возможной задержкой до 30 секунд. Наблюдения, история, отчёт и последние 30 резервных копий находятся в `/var/lib/promet-parser` и не перезаписываются Git. Сборщик работает от отдельного системного пользователя с ограничениями CPU/памяти и записи в файловую систему. В сайт атомарно публикуется только index.html. Каждый обработанный товар сохраняется отдельно; при прерывании уже полученные цены остаются. История хранится за два года, по последнему наблюдению предложения за неделю МСК.

Проверки:

```sh
curl -I https://pars.promet.pw/
# Без авторизации ожидается 401, в браузере после входа — страница.
systemctl list-timers promet-parser-refresh.timer
systemctl status promet-parser-refresh.service
journalctl -u promet-parser-refresh.service -n 30 --no-pager
```

На сайте отображаются прогресс, ошибки и дата проверки каждой цены; обновите страницу для просмотра хода сбора. При аварийном прерывании статус «идёт сбор» может остаться до следующего запуска. Подробный отчёт: `/var/lib/promet-parser/last-refresh.json`. Код выхода сборщика 2 означает, что не обновилось ни одной цены.

### Ограничения сбора

Читаются только однозначные Product/Offer с ценой RUB и наличием. Соблюдаются robots.txt, паузы и таймауты, CAPTCHA не обходится. При 403 или ошибке сохраняются прежние цена **и checkedAt**, а причина выводится отдельно. Изменение цены более 50% требует ручной проверки; для подтверждённого изменения можно вручную запустить скрипт с --allow-large-change.

Проверка 30.10.2026: разметка образцов profsafe.ru, Комуса и Железной мебели распознаётся. Для profsafe.ru crawl-delay составляет 300 секунд, поэтому обход занимает несколько часов и выполняется в фоне. Комус запрещает сбор этому роботу в robots.txt. ВсеИнструменты возвращают 403, включая robots.txt. Для этих двух источников нужна разрешённая выгрузка/API; автоматическое обновление не подтверждено, старые цены остаются со старой датой и ошибкой.

Цена и наличие зависят от публичных условий сайта, региональная персонализация не реализована. Акции, доставка, условные и зачёркнутые цены автоматически не проверяются: при успешной проверке прежние условия очищаются или помечаются как непроверенные. Счётчик покупок Железной мебели читается при наличии явного поля.

Вход защищает серверный сайт. Ранее опубликованный снимок данных и HTML в публичном GitHub остаются публичными.

Тесты: `python3 -m unittest discover -s tests -v`.

### Обновить уже установленный сервер

```sh
sudo promet-parser-update --code-only
```

Эта команда обновляет Git без принудительного сброса и пересобирает страницу с серверными данными. При сборке добавляются новые карточки, связи и цены safe.ru из выпуска. Более свежие серверные наблюдения выигрывают; прежняя история объединяется. Рабочий JSON на диске меняется только сборщиком, который также выполняет объединение перед новым прогоном и сохраняет резервную копию.

Если команда обновления еще не установлена, в существующем клоне:

```sh
cd /opt/promet-parser
git pull --ff-only
python3 scripts/build.py --output /tmp/promet-index.html
sudo install -m 644 /tmp/promet-index.html /var/www/pars.promet.pw/public/index.html
```

Если уже существует `/var/lib/promet-parser/observations.json`, вместо последней сборки используйте:

```sh
sudo -u promet-parser python3 /opt/promet-parser/scripts/build.py --data /var/lib/promet-parser/observations.json --output /var/www/pars.promet.pw/public/index.html
```

Не копируйте выпуск поверх рабочего JSON. Не переустанавливайте пароль или Nginx ради обновления интерфейса. После обновления откройте каталог и выполните Ctrl+F5.

### Последовательный сбор и HTTP 429

Региональный сборщик `scripts/refresh_regions.py` делает запросы последовательно с паузой 15–30 секунд; более длинный crawl-delay сохраняется. При HTTP 429 источник останавливается до конца запуска. `Retry-After` поддерживает секунды и HTTP-дату. Без него минимальная пауза — 15 минут; при следующих ограничениях она удваивается до 24 часов. Указанный сайтом более долгий срок не сокращается. Срок и число ограничений сохраняются в `runtime/request-pacing.json`, включая перезапуски. Поддомены profsafe.ru используют общий лимит.

Для продолжения только необновлённых карточек Альфа-Гаранта СПб за 3 ноября 2026 года:

```bash
python3 scripts/refresh_regions.py --cities Санкт-Петербург --sites profsafe.ru --resume-since 2026-11-03
```

Укажите обычные для вашей установки `--state` и `--publish`, если они отличаются от каталогов проекта. Подтверждённые записи с датой не ранее указанной пропускаются. После каждой карточки сохраняется результат. Прежние цены при ошибках не стираются. Пропуски отражаются в отчёте, поэтому частичный запуск может завершиться кодом 2 или 3. Автоматическое пробуждение по окончании паузы не создаётся: нужен следующий запуск существующего расписания либо ручной запуск. Эти правила относятся к региональному сборщику, не к старому `refresh_prices.py`.

Проверка 03.11.2026: HEAD-запрос к одной карточке вернул 200 без Retry-After, но открытие содержимого в браузере снова дало 429. Успешный HEAD не считается успешным сбором цены. 20 прежних наблюдений СПб оставлены без изменений.
