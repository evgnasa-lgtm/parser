# Сбор по двум городам

Новый серверный runner `scripts/refresh_regions.py` обрабатывает Москву и Санкт-Петербург отдельно. По умолчанию запрашиваются оба города; `--cities Москва` или `--cities Санкт-Петербург` ограничивает запуск. Ключ кэша — город и URL. Московские сведения не подставляются в СПб. Ошибки оставляют прежнюю цену, дату и наличие. Отчёт `last-refresh.json` содержит ожидаемые, обновлённые, ошибочные и пропущенные карточки по городам и дилерам. Код завершения: 0 — все подтверждены, 3 — частично, 2 — ни одной. Это не гарантия получения всех цен.

## Статус внедрения

Реализована и проверена оркестрация двух городов. Адаптеры выбора региона на четырёх живых сайтах пока не подтверждены для серверных HTTP-запросов. Поэтому без локальной настройки попытки заканчиваются явной ошибкой «Регион не настроен», сохранённые наблюдения не затираются. Не включайте это обновление как замену работающего расписания до проверки адаптеров. Данные ручного сбора СПб остаются доступны при сборке.

Следующий обязательный этап: на каждом дилере определить поддерживаемый способ передачи города (официальная выгрузка/API либо региональный cookie публичной сессии), проверить индикатор текущего города и соответствие цены/наличия видимой карточке. При CAPTCHA/403 требуется разрешённый дилером канал; обход защиты не реализован. Текущий HTTP-парсер извлекает Product/Offer и счётчик ЖМ; акции и условные цены автоматически не подтверждает. Не считать их обновлёнными вместе с основной ценой.

## Локальная конфигурация администратора

`/var/lib/promet-parser/regions.json`: объект с ключами «Москва», «Санкт-Петербург», внутри — точные hostname дилеров. Каждая запись содержит `cookie` (необязательный, только выбор города без авторизации) и `cityPattern`: проверенное регулярное выражение с именованной группой `(?P<city>...)`, которое выделяет единственный индикатор выбранного города, а не название из меню всех городов или рекламного текста. Значение группы должно точно совпасть с запрошенным городом. Не использовать шаблон, просто ищущий слово «Москва» на всей странице. Секреты, пароли и конфигурацию с cookies в GitHub не добавлять. Значения cookie и шаблоны нельзя выдумывать; готовая конфигурация пока отсутствует.

Проверка после настройки: запускать `scripts/refresh_regions.py --state /var/lib/promet-parser --publish /var/www/pars.promet.pw/public --cities Санкт-Петербург --limit 4`. Проверить каждый дилер отдельными контрольными карточками; общий лимит 4 не гарантирует охват четырёх дилеров. Удалить `--limit` только после проверки. Отдельная кнопка в статическом дашборде серверный запуск не выполняет.

Региональная проверка должна предшествовать записи наблюдения. Сохранение результата без `cityVerified=true` и точного совпадения города запрещено. Тестовые цены используются только в tests/, не в файлах мониторинга.

Существующий сервис и старый сборщик refresh_prices.py не изменены. Новый runner запускается отдельно и не подключён к расписанию до подтверждения четырёх адаптеров.
