# Надёжность сбора: 5 ноября 2026

## Основание и фактическая архитектура

Проверен исходный проект evgnasa-lgtm/parser, база до изменений —
63e7f41098836a3e1ba952235afc6dea868e69c4. Это Python 3.10+ со стандартной
библиотекой, JSON, статический HTML, Nginx и systemd. PostgreSQL, Kafka,
Spark и Airflow в этом проекте не обнаружены. Соответствующие предположения
Deep Research, Kafka-lag, Spark UDF/shuffle и партиционирование PostgreSQL
не применялись. Потоковая обработка для текущего реестра не обоснована.

## Правила качества

- Денежные значения положительные, менее 10 млн рублей. Пробелы, NBSP,
  узкий NBSP и десятичная запятая нормализуются; округление Decimal HALF_UP
  до копеек. NaN, infinity, bool, экспоненциальная запись и отрицательные
  значения отклоняются. Курс валют не угадывается: только RUB/RUR.
- Product URL сопоставляется с полным адресом: домен, город и параметры
  варианта сохраняются. Удаляются только fragment, utm_*, gclid и yclid.
  Единственный Product с явно чужим URL также отклоняется.
- Наличие «Нет в наличии» допускает отсутствие цены. Оно не превращается
  в наличие и не получает выдуманную цену. Неизвестная цена — null.
  Неподтверждённые карточки сохраняют последнее успешное наблюдение,
  checkedAt, URL и соответствия; ошибка обновляет только сведения о попытке.
- Результат проверяется целиком до изменения карточки. Применять более
  старое наблюдение нельзя; даты приводятся к UTC. Наивные старые даты
  интерпретируются как UTC для совместимости.
- Изменение цены более 50% требует ручной проверки либо явного
  --allow-large-change. Счётчик продаж не обнуляется при пропуске,
  а помечается soldUnitsVerified=false.
- Акционные, зачёркнутые и условные цены не выводятся из обычного Offer.
  После автоматического обновления они сбрасываются и promoVerified=false;
  прежние значения остаются в истории. Это не означает «акций нет».
- Региональный сбор сохраняет независимые сессии и требует подтверждения
  выбранного города. Старый сборщик не объявляет город подтверждённым.
- Реестр проверяется до объединения и сборки: нужны id, site, URL и
  списки own/analogs. Конфликтующие дубли прерывают операцию вместо
  неявной потери карточки. Разные SKU на одном URL не объединяются.

## Повторы, лимиты и восстановление

Оба сборщика используют persistent request-pacing.json. Запросы
последовательные, пауза 15–30 секунд, с соблюдением более длинного
robots crawl-delay на каждой повторной попытке. Поддомены profsafe.ru
и www-варианты делят лимит. robots.txt обязателен, ошибка его получения
не разрешает сбор. Таймаут запроса 25 секунд, лимит ответа 8 МБ.

408/500/502/503/504, временная сетевая ошибка и таймаут: максимум три
попытки с экспоненциальной задержкой и случайной добавкой. HTTP 403/404,
ошибки разметки и валидации не повторяются. HTTP 429 останавливает
источник до конца запуска и сохраняет срок ожидания для следующего.
Retry-After поддерживает секунды и HTTP-дату; срок более минуты при 5xx
сохраняется в состоянии вместо длительного удержания процесса.

Одновременный запуск блокируется ОС на Linux и Windows. Состояние JSON
сохраняется атомарно после каждой карточки. HTML пересобирается в начале,
не чаще раза в минуту и обязательно в конце. При аварийном завершении
между записями HTML может отставать от JSON; повторная сборка восстанавливает
представление. Это не транзакция между двумя файлами.

## История и хранение

Все изменения внутри одной недели сохраняются. Прежнее недельное сжатие
и автоматическое удаление истории через 735 дней убраны, точные дубликаты
снимков удаляются идемпотентно. Историю, уже потерянную прежней версией,
восстановить без резервных копий невозможно.

JSON остаётся основным совместимым хранилищем. После завершения запуска
создаётся вторичный runtime/history.sqlite3: снимки защищены уникальным
SHA-256, индексы — город/группа/сайт/URL/дата и дата. Повторная загрузка
того же снимка не создаёт дубль. SQLite не публикуется в GitHub и не
нужен для показа страницы. Его можно восстановить из JSON, но ранее
удалённые из JSON снимки потребуют резервной копии SQLite.

Рост истории пока не ограничен намеренно: удаление допускается только
после проверки отдельного архива. Для больших объёмов следующий этап —
выборка ограниченного периода в HTML из SQLite; текущая версия сохраняет
полную совместимость JSON. Первичный импорт архива пропорционален истории.
Объединение истории выполняет дедупликацию один раз на группу вместо
повторного полного прохода для каждой карточки.

## Наблюдаемость и эксплуатация

- stdout — JSON-события с runId, at, site, id, ошибкой и городом для
  регионального сборщика; systemd сохраняет их в journald.
- runtime/last-refresh.json — updated/failed/skipped/expected, полнота,
  длительность, скорость, число пересборок, сетевые запросы/повторы/ошибки.
- runtime/metrics.prom — счётчики последнего запуска в формате Prometheus
  textfile. Сам Prometheus и доставка уведомлений не устанавливались.
  Администратор может подключить файл к своему textfile collector.
- Базовые условия тревоги: failed > 0, complete=false, отсутствие успешного
  суточного запуска. Для проверки свежести используйте attemptedAt/completedAt
  в JSON. running=true после остановки процесса означает незавершённый запуск.

Коды регионального сборщика: 0 полный успех, 3 частичный, 2 нет обновлений.
Для совместимости старый refresh_prices.py сохраняет 0 при наличии хотя бы
одного обновления, 2 без обновлений; полнота отдельно в complete.
Существующий systemd unit по-прежнему вызывает старый сборщик. Переключать
его на региональный можно только после настройки адаптеров всех нужных
источников. Неподтверждённые региональные адаптеры не добавлялись.

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build.py
python3 scripts/refresh_regions.py --cities Москва --limit 1
```

Последняя команда делает настоящий запрос; тесты используют только локальные
фикстуры и подставные сетевые ответы. Синтетические цены никогда не пишутся
в data/observations.json. Linux CI запускает также проверки Nginx; Windows
явно пропускает два POSIX-теста.

## Резервная копия и откат

Перед доработкой сохранены полный локальный проект с незакоммиченными
изменениями и отдельный ZIP исходного GitHub-коммита. Запуски сборщика
продолжают сохранять последние 30 JSON-копий в runtime/backups.
Перед обновлением сервера остановите таймер и дождитесь завершения сервиса,
скопируйте каталог программы, runtime и public, затем установите проверенный
коммит и выполните сборку с runtime/observations.json. Не удаляйте regions.json
и request-pacing.json. Для отката восстановите прежний код и при необходимости
JSON/public из одной резервной копии. Развёртывание на сервере выполняется
отдельно от публикации кода в GitHub.
